## Цель проекта
Необходимо реализовать REAS API для мобильного приложения чата с LLM.
Проект реализуется в качестве курсовой работы при обучении в университете.
Функциональность мобильного приложения:
- Экран регистрации, пользователь вводит логин и пароль и получает токен, после чего считается авторизованным.
- Экран логина, ранее зарегистрированный пользователь вводит логин и пароль и получает токен (можно залогинисться на новом устройстве или после истечения срока действия токена).
- Если какой-то запрос неуспешен по причине истечения срока действия токена, открывается экран логина для ввода логина и пароля.
- Экран со списком чатов, можно провалиться в ранее созданный чат или создать новый чат.
- Экран чата, можно отправить сообщение в чат, получить ответ, пролистать историю сообщений или перейти в список чатов назад.

## Нужно реализовать следующие endpoint-ы

### POST /auth/register
   Принимает body
   ```json
   {
     "login": "...",
     "password": "..."
   }
   ```
   При получении запроса Authorization токен не проверяется, запрос допускается к бизнес-логике.
   При получении запроса нужно выполнить проверки:
   1 - Проверить наличие логина из запроса в БД. Если пользователь с таким логином уже существует, отправляется ответ 200 с телом
   ```json
   {
     "status": "Error",
     "message": "Ошибка регистрации - логин занят"
   }
   ```
   2 - Проверить длину логина и пароля, при превышении длины 100 символов в логине или пароле, отправляется ответ 200 с телом
   ```json
   {
     "status": "Error",
     "message": "Длина логина и пароля должна быть не более 100 символов"
   }
   ```
   Если проверки прошли успешно, нужно:
   1 - зашифровать пароль с помощью BCryptPasswordEncoder,
   2 - сохранить в БД нового пользователя
   User:
   Long id;
   String login;
   String encodedPassword;
   3 - сгенерировать jwt токен, в поле subject которого указать id пользователя, установить срок действия - 30 суток. Отправить пользователю ответ 200 с телом
   ```json
   {
     "status": "Success",
     "user_id": <long>,
     "access_token": "<сгенерированный токен>"
   }
   ```

   Если проверки прошли успешно, нужно:
   Сгенерировать jwt токен, в поле subject которого указать id пользователя, установить срок действия - 30 суток. Отправить пользователю ответ 200 с телом

### GET /chats/{user_id}
   При получении запроса проверяется заголовок Authorization: Bearer <token>. Если токен отсутствует, не валиден или истек срок действия, запрос не допускается к бизнес-логике и отправлятся ответ 401 Unautorized.
   Далее необходимо извлечь user_id из поля subject токена и сравнить его значение со значением user_id из запроса. Если они не совпадают, возвращается ответ 403 Forbidden.
   Если проверки прошли успешно, нужно получить список чатов из БД по user_id (список всех чатов данного пользователя) и вернуть ответ 200 со списком чатов в теле ответа:
   ```json
   {
     "chats": [
       {
         "id": <Long>,
         "title": "<строка>"
       },
       {
         "id": <Long>,
         "title": "<строка>"
       }
     ]
   }
   ```

### GET /chat/{chat_id}
   При получении запроса проверяется заголовок Authorization: Bearer <token>. Если токен отсутствует, не валиден или истек срок действия, запрос не допускается к бизнес-логике и отправлятся ответ 401 Unautorized.
   Далее необходимо извлечь user_id из поля subject токена, по значению chat_id из запроса получить user_id из БД. Если user_id из токена и из БД для данного чата не совпадают (то есть данный чат не принадлежит данному пользователю), возвращается ответ 403 Forbidden.
   Если проверки прошли успешно, нужно получить список сообщений чата из БД по chat_id, отсортировать по возрастанию параметра creation_time и вернуть ответ 200 со списком сообщений в теле ответа:
   ```json
   {
     "messages": [
       {
         "id": <Long>,
         "creation_time": <Long>,
         "text": "<строка>",
         "is_question": <Boolean>
       },
       {
         "id": <Long>,
         "creation_time": <Long>,
         "text": "<строка>",
         "is_question": <Boolean>
       }
     ]
   }
   ```

### POST /chat/new
   Принимает body
   ```json
   {
     "message": "<String>"
   }
   ```
   При получении запроса проверяется заголовок Authorization: Bearer <token>. Если токен отсутствует, не валиден или истек срок действия, запрос не допускается к бизнес-логике и отправлятся ответ 401 Unautorized.
   Далее необходимо извлечь user_id из поля subject токена для дальнейшего использования в бизнес-логике.
   Создать новый чат в БД, указав значение user_id из токена, в качестве поля title взять первые 30 символов из сообщения, или все сообщение, если оно короче.
   Создать новое сообщение с параметрами: text = message из body, creation_time = текущее время на сервере (миллисекунды с 1 января 1970 года), chat_id = id нового созданного чата, is_question = true, id - присваивается БД по порядку.
   Отправить текст сообщения (message из body) в LLM с помощью ChatClient, получить ответ LLM, сохранить его в БД как сообщение (text - это ответ LLM, is_question = false, остальные параметры указываются как выше).
   Вернуть ответ 200, в теле которого передается Message - ответ LLM:
   ```json
   {
     "id": <Long>,
     "chat_id": <Long>,
     "creation_time": <Long>,
     "text": "<String>",
     "is_question": false
   }
   ```
