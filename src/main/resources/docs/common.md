Общие правила при разработке проекта

- Сущности реализуются по шаблону MVC. Контроллеры принимают запрос и обращаются к сервисам. Сервисы содержат бизнес логику и обращаются к репозиториям для доступа к БД.
- Связь с БД с помощью spring data jpa - по возможности писать только интерфейсы для доступа к таблице БД.
- Unit тесты писать сразу не нужно - при необходимости писать отдельной задачей. Но код должен быть декомпозирован для покрытия тестами, сущности кода декомпозировать так, чтобы было очевидно, какие кейсы в тестах должны быть.
- Это pet-проект, не нужно усложнять реализацию, но не должно быть лапши и путаницы. Для решения задач использовать паттерны проектирования, там где нужно.
- Код должен быть по возможности прост, понятен и читаем человеком.
- Кодстайл может быть любой, при оформлении кода использовать наиболее часто принятые при разработке варианты оформления, но стиль оформления кода по всему проекту должен быть одинаковым.
- В приложении могут оставаться ранее добавленные файлы, которые использовались для настройки и проверки работы проекта. Может быть заметно, что они далее не будут использоваться. Их не нужно трогать, при необходимости они будут удалены вручную позднее.
